A PERGUNTA DA CURADORIA

“Isso economiza tempo de quem faz front-end, e dá para explicar o porquê em uma linha?”

Se a resposta for sim, mande. Se precisar de três parágrafos para convencer, provavelmente não é para cá.

Dois caminhos

Pelo formuláriosem Git

Preencha uma issue no GitHub com nome, link, categoria e a linha. Um bot transforma em pull request e você acompanha por lá.

Pelo YAMLcom Git

Faça fork, crie um arquivo em data/resources/ e abra o PR. O CI valida o schema e os links.

# data/resources/kugiri.yaml
name: kugiri
url: https://edoardolunardi.github.io/kugiri
area: build
category: animation
pricing: free
description:
  pt: "Divide texto em linhas, palavras e letras…"

O que entra

  • Ferramentas, bibliotecas, cursos, inspiração e comunidades de front-end.
  • Coisas que você usou ou testou de verdade.
  • Recursos pagos, desde que o preço esteja claro.
  • Projetos pequenos e desconhecidos, se forem bons.

O que não entra

  • Listas de listas e agregadores sem curadoria.
  • Links de afiliado ou recursos pagos para aparecer.
  • Projetos abandonados, sem atualização ou com o site fora do ar.
  • Descrições de marketing: “revolucionário”, “o melhor”, “incrível”.
