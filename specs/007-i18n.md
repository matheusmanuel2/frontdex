# 007 — Idiomas

Status: aprovada · Depende de: 003 · Agente: Front-end Builder

## Regras

- Idiomas: **pt-BR (padrão)** em `/pt` e inglês em `/en`. Slugs iguais nos dois.
- `/` escolhe o idioma num middleware pequeno, por esta ordem:
  1. Cookie `NEXT_LOCALE` (escolha anterior do visitante).
  2. `Accept-Language`: português → `/pt`; outro idioma → `/en`.
  3. Sem idioma do browser: país (`x-vercel-ip-country`). Lusófonos (AO, BR, PT, MZ, CV, GW, ST, TL) → `/pt`; outros → `/en`.
  4. Sem sinal → `/pt`.
- Só `/` redireciona. Motores de busca recebem sempre a URL do idioma; nunca há redirect por IP noutras páginas.
- Seletor de idioma sempre visível no cabeçalho; grava o cookie.
- `<html lang="pt-BR">` / `<html lang="en">`; `hreflang` para pt, en e `x-default` → `/pt`.
- Sem fallback silencioso: um recurso sem descrição num idioma não é publicado (spec 001).

## Onde vive cada texto

| O quê | Onde |
| --- | --- |
| UI | `messages/pt.json`, `messages/en.json` (next-intl) |
| Recursos | campos `pt`/`en` no YAML |
| Áreas, categorias, coleções | campos `pt`/`en` nos YAML de apoio |
| Páginas longas (Sobre, Contribuir) | MDX por idioma |

## Critérios de aceitação

- [ ] O CI falha se uma chave existir num `messages/*.json` e não no outro.
- [ ] Testes Playwright cobrem os 4 casos do middleware.
- [ ] Trocar de idioma numa página mantém a mesma rota no outro idioma.
